## 一、教材資料依據

完整解析 [corpus.json](../corpus.json) 的 45 筆課程記錄，檢視所有課文、生詞及語法欄位型別；三冊各 15 課，按 JSON 陣列順序累積。每筆包含「冊」「課」、對話1／對話2／文章1／文章2 及各部分的「生詞」「語法點」。

- 非空文本：對話1 為 45、對話2 為 15、文章1 為 30、文章2 為 0。
- 生詞欄位合計 1,563 筆，包含跨課重複，不能當作不重複已學詞總數。
- 沒有人工校訂斷詞、獨立人名表或學生個別學習紀錄。
- 第一冊第一課（JSON 第3–63行）有「請問、你好、台灣」等對話1生詞；對話2另有「喝、茶、咖啡」；課文說話者有明華、月美、開文與凱文。這些標籤如有教材校訂疑問，不能自行合併或改名。
- 語法欄位混合「問句：您貴姓？」「問句：嗎」「肯定回答」等形式，不能把每項都稱為完整例句。

[README.md](../README.md) 說明外部 LLM 與字典回退，標題仍為 v1.9；app.py 顯示 v2.2，文件版本尚未一致。本次不修改 README。[DEVELOPMENT.md](../DEVELOPMENT.md) 記錄測試與環境。

## 三、目前功能流程與判定細節

### 教材、已學詞彙與目標詞

[app.py](../app.py):91 定義四個文本部分。選課保留 DATA 的全域索引 idx（785–788行），並不在切換冊別時清空先前冊的已學集合。get_lexicon() 使用歷課含本課的生詞聯集；來源文本的 target 則是 words(lesson, [reference])（841行），所以「當次目標」不等於整課生詞，也不等於所有已學詞。

curriculum_evidence() 累積全課文斷詞及語法欄位全形冒號後文字；沒有冒號者不提供語法斷詞證據。「貴姓」另有硬編碼加入。課文片段用於連續用詞比對。

### 人名與斷詞

build_tokenizer():26 優先使用根目錄 dict.txt.big，其次 dictionaries/dict.txt.big；清理格式後寫暫存檔，少於1,000筆有效詞條或初始化失敗時回退預設字典。格式檢查及初始化不等於教學正確性。dictionaries/teaching_words.txt 僅在存在時載入；本基準未提供此檔。

names_from_dialogue():187 讀行首1–8字元的冒號標籤；explicit_names_from_source():199 用「我是、我叫、這是」句型產生候選，可能把「老師」等非姓名誤列。speaker_warnings():250 只核對教師核准清單，且介面只在「對話」模式呼叫（882行）。cleanbody():153 去除部分標題及行首最多12字的冒號前綴，可能同時刪除一般敘述前綴。

audit() 對教材／核准集合中的多字詞先做最長比對，剩餘片段交 Jieba，HMM=False。不使用詞性或通用人名辨識模型。即使註解強調避免用已學單字拼新詞，也不能由此保證所有複合詞都不漏報。

### 複現、超綱與相似度

audit() 的 baseline 是已學生詞、教師允許詞、課文證據、語法證據、核准人名之聯集；另有固定功能字集合。計數分類依序為核准人名、已學生詞、語法例句、課文斷詞／連續子字串、教師允許詞、功能字，剩餘列「疑似超綱」。分類先後只決定顯示證據，不代表教師訂定的學習程度排名。

多字 token 若為任一歷來課文／語法片段的子字串，也可視為課文證據。未含漢字的 token 不計入超綱詞次。目標詞以清理正文中的非重疊子字串計次；例如「是不是學生」對「是」計2次，與語言學獨立詞次不等同。

覆蓋概念為「出現至少一次的目標詞項數／目標詞項數」，次數表則逐詞列次數，重複出現不能增加覆蓋分子。空目標集合的百分比語意尚待確認。當前只彙總全部貼入內容。60%／80% 是介面與提示詞選項，並非本文件批准的統一門檻。

ngram_overlap():167 與 SequenceMatcher 提供連續8漢字重合及字元相似度；899行的0.25／0.7只觸發提醒，不能判斷情節是否新穎或構成語意抄改。count_han():163 只數清理後漢字，不數英數標點。901行以單篇下限及 n 倍上限檢查總字數，不是逐篇檢查。

### LLM 提示詞與教師定稿

- prompt1（861–872行）：產生1–3篇對話／短文提示詞，包含來源、目標生詞／語法、字數、人物、引導詞及覆蓋需求；沒有附完整累積詞庫。
- prompt2（926–935行）：以 Python 檢測線索與教師意見建議修訂，排除教師保留詞；仍由外部 LLM 處理。
- prompt3（973–992行）：以 final_text 命題，附累積詞庫、允許詞、多語釋義、文字差異線索；要求先內容、再語言自檢並輸出 JSON。
- compare_changes():320 只提供文字差異，不證明情節或事實差異。quiz_revision_prompt():583、inspect_questions():519 目前未接到主介面呼叫，不視為正在執行的獨立修題流程。
- 942行確認定稿要求文本、人名、引導詞仍與檢測快照相同，並無未核准說話者。第三階段受 approved 控制，但第四階段可直接貼 JSON。

### 閱讀測驗、JSON 與補充詞

parse_learning_json():603 檢查文本、title/type、題幹、選項陣列、答案等型別；可接受 Markdown 包裹 JSON。JSON 欄位包括 title、reading_texts、supplementary_vocabulary、instructions、questions、validation_warnings。型別通過不等於內容正確。

inspect_structured_quiz() 檢查題數、題型、單選四個非空且文字不同的選項及 A–D 答案等；不判斷四個不同文字是否同義正解。支援 single_choice／true_false／short_answer／ordering；混合題型沿用各題 type。

normalized_glossary() 同詞合併來源 reading/question 與多語解釋；同語言不同非空解釋後者覆蓋前者。missing_glossary_explanations() 只驗非空，不驗翻譯。json_to_editors():668 轉為可編輯純文字後，editable_quiz_checks():768 只補基本題數、選項數及答案項數。split_items():508 有至少3字元的題幹條件，可能漏計短題幹。

quiz_vocab_review() 先用基本允許集合檢查，再加入補充詞檢查，比較「已由補充生詞涵蓋」與「尚未解決」。它不以釋義是否完整或是否列印為條件；保留詞不是永久升級為已學詞。

### Word 輸出

write_docx() 以 BytesIO 產生 A4 docx，設定 Microsoft JhengHei、標題、正文、生詞及測驗；短選項可兩欄，教師答案有內容時另頁。第四階段可編輯正文與答案，並勾選是否列印補充詞；空正文不可匯出，無題目仍可匯出閱讀文本。異常提醒不阻擋下載。程式不替教師驗證文意或多語釋義。

## 五、待教師確認的決策

| ID | 待教師確認事項 | 決策需要的內容 |
|---|---|---|
| Q01 | 已學範圍 | 當課全部部分／僅選定部分／已完成課次；課文出現但未列生詞是否即已學；語法片段是否同等證據 |
| Q02 | 人名 | 歷來名字自動允許或教師勾選；全名／簡稱／角色稱謂的對應與未知正文姓名的處理 |
| Q03 | 複合詞拆分 | 已學單字、多字詞重組及課文子字串是否足以證明複合詞已學；提供正反例 |
| Q04 | 覆蓋與次數 | 完整詞／子字串／詞形變體計次；逐篇或合計；是否設60%／80%門檻、空目標分母及篇章邊界；暫不訂硬性門檻 |
| Q05 | 功能詞例外 | 是否採固定免檢清單、哪些項目、是否受課次限制；「貴姓」等特例須否保留 |
| Q06 | 超綱保留與解釋 | 可保留的量、缺釋義或缺語言、取消列印時提醒／阻擋方式；空語言選擇與同詞多語釋義衝突 |
| Q07 | 命題後重檢範圍 | 已確認須重檢題目；是否擴及教師答案、釋義及所有正文編輯；技術錯誤或教學警告如何呈現 |
| Q08 | 定稿與匯出 | 能否直接載入未定稿稿件、正文變更後如何重新核准、僅閱讀版的允許流程及人工覆核記錄 |
| Q09 | 自然度與新文本 | 如何人工評估情節變化、語法複現、難度、推論負荷與可接受字數；不從現有相似度數值創造教學標準 |

確認方式：由教師針對 ID 提供決定與正反例，再於後續授權任務更新文件及實作；未確認前保留現行行為並明示限制。
